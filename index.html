Veelgemaakte fouten (examen)

VLAN & Access-poorten

  • VLAN bestaat wel, maar poort staat nog in VLAN 1
  • VLAN niet aangemaakt op alle switches
  • Access-poort verkeerd geconfigureerd als trunk
  • Vergeten no shutdown op SVI

Trunking

  • switchport mode trunk ontbreekt
  • VLAN niet toegestaan in allowed list
  • Native VLAN mismatch
  • DTP veroorzaakt onverwachte trunk

DHCP

  • Geen excluded-address ingesteld
  • Verkeerde default-router in pool
  • DHCP-pool gebruikt verkeerd netwerk
  • SVI down → DHCP werkt niet

ACL

  • ACL op verkeerde interface geplaatst
  • Verkeerde richting (in / out)
  • Permit any any vergeten
  • Bron en bestemming omgedraaid

Scenario-variaties met antwoorden

Scenario 1 – DHCP probleem

Vraag:
Apparaten krijgen geen IP-adres via DHCP. Hoe pak je dit op?

Oplossing / aanpak:

  1. Controleer of de interface en SVI actief zijn
  2. Controleer of het apparaat in het juiste VLAN zit
  3. Controleer of de DHCP-pool bestaat
  4. Controleer excluded addresses
  5. Controleer of de default gateway klopt

Commando’s:


show ip interface brief
show vlan brief
show ip dhcp pool
show running-config | section dhcp

Scenario 2 – Trunk werkt niet

Vraag:
Een VLAN bestaat, maar verkeer komt niet door over de trunk. Wat controleer je?

Oplossing / aanpak:

  1. Controleer of de poort in trunk mode staat
  2. Controleer of het VLAN is toegestaan op de trunk
  3. Controleer of de trunk aan beide kanten identiek is
  4. Controleer native VLAN instellingen

Commando’s:


show interfaces trunk
show running-config interface fastethernet0/1

Scenario 3 – ACL blokkeert te veel verkeer

Vraag:
Na het instellen van een ACL werkt intern verkeer niet meer. Wat kan fout zijn gegaan?

Oplossing / aanpak:

  1. Controleer of de ACL op de juiste interface staat
  2. Controleer de richting van de ACL (in of out)
  3. Controleer de volgorde van de regels
  4. Controleer of een permit-regel aanwezig is
  5. Controleer of bron en bestemming correct zijn

Commando’s:


show access-lists
show running-config interface vlan

Scenario 4 – OSPF neighbor komt niet online

Vraag:
OSPF routers zien elkaar niet als buren. Wat kan de oorzaak zijn?

Oplossing / aanpak:

  1. Controleer of beide routers in dezelfde OSPF area zitten
  2. Controleer het network statement en wildcard mask
  3. Controleer of de interface niet passive is
  4. Controleer of de interfaces up zijn
  5. Controleer Layer‑3 connectiviteit

Commando’s:


show ip ospf neighbor
show ip ospf interface
show ip interface brief
